# RECAP v3：从 base 重训，真机/孪生平衡（2026-11-12）

用户决定：从官方 SmolVLA base 重新微调，真机和仿真比重相同，人工纠错适度加权。配置 `configs/so101_recap_v3.json`，输出 `runs/so101_recap_v3`。

## 初始化和训练

- 从 `artifacts/smolvla_base` 初始化，不加载 v5 或 RECAP v2 的策略权重，重新建立优化器，全量微调。
- 20000 个优化器更新，有效 batch 64（16 × 梯度累积 4）。
- 学习率峰值 1e-4，1000 步线性预热，之后余弦衰减到 2.5e-6。每 1000 步验证、保存 best/last 和恢复状态。
- 保留现有 RECAP 标签、dropout 0.3 和静止段裁剪规则。标签来自既有 value v1，本轮没有重训价值函数，也没有同时更改标签规则。

## 采样

`so101vla/recap_sampling.py` 的 `BalancedSampler` 每个 16 帧小批固定抽 8 帧真机、8 帧孪生，再打乱顺序。真机内部仅对人工接管的正确帧给 2 倍权重；纠错段中的模型控制帧不加权，孪生夹空也不计为人工纠错。

旧的 `correction_repeat` 保持为 1，避免它按整段重复数据。新采样器由相同 NumPy RNG 驱动，恢复状态仍记录预取批次之前的 RNG，验证了采样和标签 dropout 的恢复一致性。

实际训练可用起点：真机 284807、孪生 111800，共 396607，其中真机人工纠错 16145。160000 次采样审计结果：

- 真机 50%，孪生 50%；
- 人工纠错占真机抽样 10.75875%，理论值 10.72929%；
- 按任务：钥匙约 25.38%，玩偶约 24.62%，object 50%。

## 验证和缓存

- 原有 11 段真实示教验证和 2 段未知成败测试划分不变。
- 从新增 twin v2/v2b 中留出 40 段未故意夹空的成功专家轨迹：左右侧 × 五类形状，每组四段，种子 20261112。它们完全不参与本轮策略采样。
- 共 51 段验证，510 个观测起点（真机 110、孪生 400）。每组动作 MAE 各自归一化后，按真机 50% + 孪生 50% 的平均值选 best，同时保留原总体和每任务误差。该指标是离线动作误差；抓取/入盒能力仍需孪生闭环和真机验证。
- 复用 v2 已验证的两路 JPEG 缓存，核对数据表、标签、归一化、缓存路径及完整 SHA256；只重建划分和采样数组，没有重新解码视频。顶视 `/dev/shm/recap_v2`，腕部 `/root/sj-fs/cache_recap_v2`。
- 两步冒烟测试通过，动作专家全部 16 层、视觉编码器、connector、语言模型梯度正常，峰值分配显存约 22.42 GB（十进制）。

## 服务器启动和备份

由 `scripts/train_with_backup.py --config configs/so101_recap_v3.json` 启动，启动记录为 `runs/so101_recap_v3/launch.json`，训练日志 `train.log`，管理进程日志 `launcher.log`。

best 更新后，管理进程把完整 best 复制到网盘 `/root/sj-fs/so101_recap_v3/best`，按 SHA256 校验后发布；配置、划分和轻量日志一起保存。原目录的 last 和优化器恢复状态保留在数据盘，未复制到网盘。此脚本不会自动关机。

训练结束后用同一批孪生闭环场景比较 v2/v3，分别记录 30/50 步执行长度；参考 `recap-v2-twin-eval.md`，避免把控制方式的差异算成模型改进。
