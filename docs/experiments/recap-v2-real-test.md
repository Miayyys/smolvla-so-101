# RECAP v2 钥匙串真机测试（2026-11-12 准备）

目标：与 v5 在同一时段、同一钥匙串/盒子/摆放位置和起始姿态下比较，重点记录左侧抓取及夹空后是否重新对准。任务指令统一为 `Put the key in the white box.`。

## 准备检查

- 模型：`runs/so101_recap_v2/best`，第 5000 步；已核对服务器权重 SHA256，资源路径已改成本机路径。
- 基线：`runs/so101_full_v5/best`。
- 从臂 6 个舵机通信与标定读取通过；检查只读取寄存器，没有发送运动指令或改变扭矩。
- 顶视 1280×720、实测约 26.5 fps；腕部 640×480、约 30 fps。白盒与钥匙串均在顶视画面内。
- 检查报告和当时的双相机画面：`runs/real_eval/recap_v2_key_preflight_20261112/`。报告中的关节位置只是检查时的读数，不是待执行的目标。
- 两模型的启动命令已 dry-run。RECAP 会自动启用 positive 标签；两者均使用 RTC（horizon 20，queue threshold 30）及 Gaussian 平滑 sigma 2。

## 首轮：RECAP v2 两段

启动前手动摆好物体、固定白盒，将机械臂放到 v5 测试使用的肩部转开姿态（肩部旋转约 50–60°，手臂折叠）。本次检查时肩部仅约 2.5°，需要先调整。后续基线测试保持相同起始姿态。

在项目根目录、可接收键盘输入的终端执行以下命令，会启动真机运动和录制：

```bash
fish scripts/eval.fish -n rollout_recap_v2_key_check_20261112 \
  -p runs/so101_recap_v2/best -t 'Put the key in the white box.' \
  -e 2 -s 60 --rtc
```

两段依次摆左、右，各一段，先确认启动、抓放和录像链路。每段上限 60 秒，段间重摆物体。按 `n` 结束当前段/在重摆后进入下一段，`r` 重录本段，`q` 或 Esc 退出。结束后终端会逐段询问成败，`y/n/s` 分别表示成功、失败、跳过。

录像在 `artifacts/datasets/rollout_recap_v2_key_check_20261112`；终端日志与成败 CSV 在 `runs/real_eval/` 下同名文件中。已有数据集时脚本会拒绝覆盖；继续同一轮需加 `--resume`，重新测试则另取名字。

## v5 对照两段

复现相同的左、右摆放及起始姿态后执行：

```bash
fish scripts/eval.fish -n rollout_v5_key_check_20261112 \
  -p runs/so101_full_v5/best -t 'Put the key in the white box.' \
  -e 2 -s 60 --rtc
```

## 正式对比

首轮通过后，两模型各测 20 段，左、右各 10 段。使用新数据集名，按小批交替测试，两模型复现同一批摆放；记录每段左右侧、起始姿态和明显的光照变化。成功定义为 60 秒内钥匙串完全落入白盒且已松爪，按结束时的状态判断；挂在盒外沿、掉出盒子或空手到盒子均为失败。成功放稳后可以按 `n` 结束并标注。

额外记录是否横抓、首次是否夹空、夹空后是否重新对准，便于判断孪生数据是否改善了目标行为。两个试跑段不足以估计成功率。
