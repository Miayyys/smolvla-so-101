# 毕设计划（2026-10-19 起草；全部为计划，未实施、未测量）

## 题目方向

低成本 SO-101 机械臂上 VLA 策略（SmolVLA）的端侧（RK3588）量化部署：以闭环任务成功率为主指标，比较 FP 基线与量化模型的成功率、推理延迟、内存与模型体积。

## 技术路线

1. 真机平台：SO-101 组装与标定，LeRobot 读写关节、双相机采图；遥操作采集示教。
2. 真机 FP 基线：用真机示教微调 SmolVLA（沿用 `so101vla/train.py`；LeRobot 数据集格式的 prepare 已在其中），在固定任务与布局集合上测闭环成功率；评测口径沿用仿真预研的结论（足够次数、逐布局配对比较）。
3. 推理时间预算：30Hz 控制、每块执行若干步时，单次推理（图像→动作块）的允许时间；以此确定端侧需要达到的速度。
4. 端侧部署：在 RK3588 上打通 SmolVLA 完整推理（视觉编码器、语言/prefix、Expert），先 FP16 再量化；起点为 `reference/qvla_rk3588/`。
5. 量化：PTQ 与 QAT，按 RK3588 后端实际支持的位宽/算子组合；混合精度（可参考 `reference/qvla_rk3588/haq/`），以任务成功率与实测延迟为约束。
6. 仿真作为辅助：大量重复的定量比较（量化前后在仿真闭环上的差异）在仿真中做，真机做验证与演示。

## 风险

- 仿真策略不能直接迁移到真机（相机、外观、初始姿态不同，见预研真机到仿真诊断）；真机需要自采数据。
- 真机上做 DAgger 没有读取真值的脚本专家，需要人工纠正。
- RK3588 上 VLA 的算子支持与精度问题（前期探查见 `reference/qvla_rk3588/docs/project-route.md`）。
- 任务范围窄（固定物体与指令）时，成功率只反映精度，不反映视觉/语义泛化。

## 路线决定：2026-11-04 转向 RK3588 端侧部署

- **浮点基线**：实验四第二阶段的 `runs/so101_full_v5/best`（全量微调；从转开的姿态起始，60 s：玩偶 17/21，钥匙 13/20），见[实验四](experiments/exp4-full-v4.md)。量化前后的比较都以它为参照，后面如果换了基线，量化要重新校准、重新测试。
- **暂缓**：左侧抓取差（钥匙左 4/10、右 9/10）、静止姿态不起步。前者以后靠补采纠错数据解决，后者靠固定的转开起始姿态绕开。
- **下一阶段目标**（对应里程碑"11 月上旬 RK3588 跑通一次完整推理并测延迟"）：
  1. 把这个基线转换到 RK3588，跑通完整推理（视觉编码器、语言/prefix、专家）。全量微调后 VLM 权重变了，QVLA 里转换好的 base 模型不能直接用。
  2. 实测板端单次推理延迟，先 FP16，再默认 INT8，与 30Hz、每块 50 步的时间预算（约 1.67 s）比较。QVLA 中 `smolvla_base` 的实测结果作参考：512 分辨率混合 INT8 约 2.9 s，图像 256 + 完整专家约 1.5 s（`reference/qvla_rk3588/docs/project-route.md`）。
  3. 用真机录到的画面，比较板端和电脑端的动作输出，作为第一步的精度检查。
- **量化方法候选**（只是梳理，未实施）：见 [quantization-methods.md](quantization-methods.md)。
- **具体方案还没有定**。开始前要确认：板子的连接方式；闭环测试时机械臂和相机接到板子上，还是由电脑采集后发给板子推理；RKNN-Toolkit2 的独立环境。
